# KotoPotok через GitHub Actions — пошагово

Это бесплатный и круглосуточный вариант без сервера. GitHub сам раз в 3 часа запускает бота, тот публикует один пост и сохраняет базу обратно в репозиторий, чтобы не повторять старое.

## 1. Аккаунт и репозиторий

1. Зайди на https://github.com и зарегистрируйся (если ещё нет аккаунта).
2. Нажми **+** → **New repository**.
3. Repository name: `kotopotok`.
4. Выбери **Public** (публичный) — так Actions будет бесплатно без лимита минут.
5. Поставь галочку **Add a README** — чтобы репозиторий сразу создался с файлом.
6. **Create repository**.

## 2. Загрузить код

1. Распакуй `kotopotok_github.zip`.
2. В репозитории нажми **Add file** → **Upload files**.
3. Перетащи туда **всё содержимое** распакованной папки, включая папку `.github` (в ней лежит workflow).
4. Нажми **Commit changes**.

Проверь, что файл появился по пути:

```text
.github/workflows/post.yml
```

Если папка `.github` не загрузилась — создай её вручную через **Add file → Create new file**, в имени напиши `.github/workflows/post.yml` и вставь содержимое файла из архива.

## 3. Секреты (токен и канал)

В репозитории: **Settings** → **Secrets and variables** → **Actions** → **New repository secret**.

Добавь два секрета:

| Name | Value |
|---|---|
| `TELEGRAM_BOT_TOKEN` | токен от BotFather (из твоего `.env`) |
| `TELEGRAM_CHANNEL_ID` | ID канала, например `@mychannel` (из твоего `.env`) |

**Никуда больше токен не вставляй.** В архиве `.env` нет специально.

## 4. Включить Actions

Открой вкладку **Actions** в репозитории. Если увидишь надпись про включение workflows — нажми **I understand my workflows, go ahead and enable them**.

## 5. Первый пост вручную

Вкладка **Actions** → слева `KotoPotok — один пост` → кнопка **Run workflow** → зелёная **Run workflow**.

Через 10–30 секунд открой лог запуска. Должно быть примерно:

```text
Разовый запуск: один пост по расписанию GitHub Actions
Бот: @твой_бот
Микс контента: коты 0% · смешное 0% · вебмы 100%
Опубликовано: ... (Wikimedia Commons, .webm)
Разовый запуск завершён: пост опубликован
```

Проверь канал — пост должен появиться. Если появился, значит дальше всё пойдёт само.

## 6. Автопостинг

schedule уже настроен:

```yaml
cron: '0 4,7,10,13,16,19 * * *'
```

Это UTC, то есть **07:00, 10:00, 13:00, 16:00, 19:00, 22:00 по Москве**. Один пост за запуск.

## Управление

В режиме GitHub Actions Telegram-команды (`/start`, `/mix`, `/pause`) **не работают** — бота нет в постоянно работающем процессе. Управляй так:

| Что сделать | Как |
|---|---|
| Опубликовать сейчас | Actions → Run workflow |
| Изменить долю контента | Открыть `.github/workflows/post.yml` → изменить `CONTENT_MIX` → Commit |
| Изменить расписание | Там же изменить строку `cron` → Commit |
| Изменить запросы вебмов | Там же `WEBM_QUERIES` → Commit |
| Поставить на паузу | Actions → workflow → **Disable workflow** |
| Посмотреть логи | Actions → нужный запуск → лог шага `Опубликовать один пост` |
| Посмотреть базу | Файл `data/bot.db` в репозитории обновляется после каждого поста |

Важно: GitHub отключает schedule, если в репозитории нет активности 60 дней. Посты сами создают коммиты с базой, поэтому проблема не возникнет, пока бот публикует.

## Если запуск красный

Открой лог и посмотри ошибку:

- `Не удалось связаться с api.telegram.org` — проверь секреты и доступность GitHub Actions.
- `Не удалось найти медиа` — Wikimedia временно не отдал ролики; следующий запуск попробует снова.
- ошибка `git push` — проверь, что в workflow есть `permissions: contents: write`.
